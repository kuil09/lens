## Findings

### P1 — DMG job cannot create its package (corrected)

`ci.yml` invoked `make package --development --format dmg`; the system make rejects those arguments before running the recipe. A read-only `make -n` reproduced both unrecognized-option errors. Also, the new job only checked out source: `needs` orders jobs but cannot transfer the app from the preceding runner. Even correcting arguments alone would still leave no app to package.

Packaging now follows the build within the same job and uses `make package ARGS='--development --format dmg'`. A venv avoids globally managed Python conflicts. Upload includes the checksum and fails if outputs are missing. A separate manual protected workflow handles real signing/notarization; ordinary CI is not relabeled as notarized.

### P2 — Explicit-source change does not establish resolution of issue #2

`RegionalTranslationPipeline.translateNext()` now directly supplies `context.source` when selected. That is consistent with the requested API configuration, and the new test confirms it while automatic mode preserves language-specific batches. However, `OCRService.detectLanguage` already returned the explicitly selected source for **any** recognized text before this patch. The old pipeline therefore already received that language from the real recognizer. An English sentence is still classified as Korean when Korean is explicitly supplied; the added characterization test demonstrates this.

Consequently this change is not proof that the user's reported behavior was fixed. If source selection is intended as an exclusion filter, a separate conservative language-mismatch policy is needed; a Vision recognition hint alone is not that filter. Do not close issue #2 without a real mismatched-language reproduction and explicit-source/automatic-mode acceptance. No Apple translation result or physical screen outcome is claimed by the mocked routing test.

### P2 — Guide reload allows overlapping refreshes (review finding)

`SystemLanguageGuideView` sets `checking` only in `.task(id: target)`. The “Check Again” button directly invokes `refresh()` without setting it. During `catalog.load(checkInstallation: false)`, `checkingInstallation` is true but `loading` is still false, so the button and target picker are not disabled by the existing conditions. Repeated clicks/target changes can launch overlapping tasks; catalog generation tokens limit published data, but do not serialize the view's status/message updates. Include `checkingInstallation`, or put checking/cancellation ownership inside a single refresh operation, before claiming robust retry behavior. This is a code-path finding; UI rapid-click reproduction was not performed.

### P2 — Published version metadata is reused for changed app code

All three upstream commits retain beta.5/build 11 even though app behavior differs from the signed beta.5 download. Do not replace or re-identify that published binary. New CI artifact names contain the full source identity via a SHA suffix and provenance; a future public release still needs a new version/build/channel. No beta.5 assets were changed by this work.
