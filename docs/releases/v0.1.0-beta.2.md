# Lens 0.1.0-beta.2 — Development Preview

> Historical record: download assets and tag retired. The instructions and results below describe this release only. Use [GitHub Releases](https://github.com/kuil09/lens/releases) for available downloads and their matching validation records.

App 0.1.0, build 6. A local screen-translation lens for Apple Silicon Macs running macOS 26.4 or later.

## Download and install

- Download `Lens-0.1.0-beta.2-6-DEVELOPMENT-NOT-NOTARIZED.dmg` and its `.sha256` sidecar from this release.
- Open the DMG and drag **Lens** to **Applications**. The image also includes the MIT license, copyright 2026 kuil09.
- The app is **Developer ID signed, with hardened runtime, but not notarized**. The DMG itself is not a signed/notarized distribution. Gatekeeper may block downloaded copies; do not disable macOS security protections. Building from this tag with Xcode 26.4 or later is an alternative.
- The bundle identifier remains `dev.local.lens`. Moving from an older ad-hoc build may require owner authorization for Screen Recording. Signature continuity does not guarantee retained OS consent.

Verify the files from their download folder:

```sh
shasum -a 256 -c Lens-0.1.0-beta.2-6-DEVELOPMENT-NOT-NOTARIZED.dmg.sha256
```

## What's new

- Native Liquid Glass controls, centered source/target swap, frosted paused lens, and transparent translation overlay.
- English, Korean, and Japanese interface localization, following macOS app-language preferences.
- Source/target pickers show downloaded translation packs with usable routes and source OCR support. Language downloads remain explicit.
- Independent settings and a three-step first-launch guide for permission, languages, and the save folder.
- One-click PNG images and silent MP4 recordings accumulate in a chosen folder with timestamped names and no overwrite.
- Permission handoff pauses translation/recording and hides the floating overlay. Returning opens normal guidance; Later remains visible; incomplete onboarding survives normal quit.
- Rechecking permission, reopening a window, or relaunching does not request permission or start capture automatically. Pending capture shutdown and video saving are drained before Lens opens Settings or quits.
- Optional local signing configuration, repository hygiene checks, and exclusion of generated/private artifacts from source control.

## Validation and known limits

Local build 6 checks passed: 63 ordinary tests (60 Swift Testing and 3 XCTest), with two installed-language opt-ins skipped. Repository checks passed 49 synthetic-index and 49 shell assertions. The exact DMG passed image/SHA-256 checks, read-only inspection, app-bundle byte comparison, strict app-signature verification, and license/metadata/privacy-manifest checks. These are local results, not a claim about GitHub Actions or clean-machine acceptance.

Actual macOS checks covered missing-permission guidance, leaving Settings and reopening Lens through Launch Services, Later, and normal quit/relaunch. **The current development host still reports missing screen permission despite a visible enabled Settings entry.** Successful authorization and return, administrator-password input, and consent retention across an authorized rebuild remain unverified. Direct Dock-click automation also failed, so that path is not claimed as manually verified.

Whole-screen OCR/translation acceptance, recording-in-progress permission handoff, clean-user install/update, offline/download recovery, multiple displays, 30-minute stability, formal translation-quality scoring, and latency targets remain incomplete for this build. This is a prerelease for testing, not a stable-release guarantee.

Screen content is processed on device. Capture exports contain the underlying screen, including when the live lens looks transparent; review files before sharing.
